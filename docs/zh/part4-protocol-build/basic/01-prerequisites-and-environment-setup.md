
# 预备知识与环境引入

## 1.在用户态模拟网络终端
在本章中，我们即将开始手动建立一个完整的 TCP/IP 协议栈。这不仅是第三章代码的逆向重新排布，而本质上是在用户态空间**模拟了一个完整的终端网络实体**。我们的自定义协议栈将接管底层的网络交互，自动处理 ARP 解析与 ICMP 请求，从而将自己正式纳入局域网的通信范围，并能够通过网关(linux内核)与全局互联网进行数据交换。

此时，你可能会对这种软件层面的网络体系感到一丝困惑：宿主机的 Linux 系统充当了网关，而我们编写的协议栈作为局域网中的独立主机。那么问题来了——**在脱离了真实网线和 Wi-Fi 物理架构的情况下，我们该如何在抽象的软件层中，将这两个网络实体进行物理级别的链接？**

### 2. TAP 设备：连接内核与用户态的虚拟网线
这就引出了 Linux 网络体系中极为核心的组件：**TUN/TAP 设备文件**。我们可以从两个截然不同的维度来理解它：
* **对于 Linux 内核而言**：它和一张插在主板上的物理网卡没有任何区别。Linux 系统会为它分配 MAC 地址、配置 IP、将其加入系统的路由表中，甚至可以将其桥接到其他虚拟机或容器网络上。
* **对于用户态程序而言**：它仅仅就是一个普通的文件描述符（File Descriptor）。就像读写普通文本文件一样，我们的程序可以自然而然地向其中写入字节流，或者从中读取数据。

**TAP 设备实际上成为了连接我们自定义协议栈与 Linux 内核的“虚拟网线”**。在现代网络工程中，它也是构建 VPN（虚拟专用网）和虚拟机底层网络的基石。而在本项目中，我们将聚焦于如何利用它来为自定义协议栈提供 L2（数据链路层）的收发能力。

### 3. 如何初始化与调用 TAP 设备
获取这根虚拟网线的操作在 C 语言中非常直观。首先，我们通过标准的系统调用打开设备：

```c
// 打开 TUN/TAP 字符设备
int fd = open("/dev/net/tun", O_RDWR);
```

正如前文所述，TAP 设备在用户态本质上就是文件描述符，调用它与操作普通文件没有显著区别。在配置时，我们通常会传入 `IFF_TAP` 标志以操作以太网帧，并附加 `IFF_NO_PI` 标志。**`IFF_NO_PI` 的作用非常关键**，它能去掉内核附加的包头信息，直接将最原始的以太网数据帧交给我们的程序，使其表现得像一根真正纯粹的物理网线。

既然它在内核中被视作独立的物理网卡，我们自然可以通过系统调用获取系统为它分配的物理 MAC 地址：

```c
struct ifreq ifr;
// ... 省略部分配置名称的代码 ...
// 获取设备的硬件 MAC 地址
ioctl(fd, SIOCGIFHWADDR, &ifr);
```

拿到这个 MAC 地址后，我们的协议栈在进行数据包封装与发送时，就可以将其作为源物理地址进行填充了。

### 4. 视角对比：TAP 设备 vs. 原始套接字 (Raw Socket)
回顾我们在第三部分的实践，当时我们使用了 Raw Socket 来实现物理网卡与用户态进程的通信。那么，本章的 TAP 设备与它有什么区别呢

* **Raw Socket（原始套接字）**：更像是一个**网络窃听器**。流量本来是要发给宿主机的，我们在第一章和第三章中通过开启混杂模式（Promiscuous Mode）并绑定网卡，强行复制或拦截了这些数据。它通常用于抓包或旁路注入。
* **TAP 设备**：在内核中充当的是**完整的网络终点**。发往 TAP 设备的数据包，在路由规则上本身就是以它为目的地的。它是真正意义上的虚拟 L2 层网卡，而不是一个旁路监听者。

### 5. 工程实践：一键启动与版本演进
为了简化协议栈的启动与调试过程，避免繁琐的手动配置，我将 TAP 设备的创建、IP 分配、路由配置等终端指令统一集成到了 Bash 脚本中。我们使用了两个脚本进行协同，旨在提供极其轻便的使用体验，并且每次运行都会重置环境，确保干净的测试状态。

你可以在项目的根目录下，直接打开终端执行以下指令来运行不同版本的代码：

**运行第一版协议栈：**
```bash
sudo bash ./04_protocolstack_underlying_c/first_version/run.sh
```
**第一版特点**：主要结合第三章的网络知识，实现了协议栈对外部连接的底层应答，完成了数据包的层层嵌套与发送，最终成功建立起基本的 TCP 连接并实现数据回显（Echo）。

**运行第二版协议栈：**
```bash
sudo bash ./04_protocolstack_underlying_c/second_version/run.sh
```
 **第二版特点**：在第一版的基础上进行了深度的架构重构。引入了协议控制块（PCB, Protocol Control Block）等关键数据结构，优化了状态管理与内存调度，使其不再是一个简单的教学模型，而是一个初具雏形、及格的工业级协议栈。
