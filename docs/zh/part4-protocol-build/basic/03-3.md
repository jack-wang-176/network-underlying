# 3实现基础 TCP 握手和数据回显

这一节我们来完成tcp数据的回显，回顾我们之前一直强调的内容这一部分主要包含两步，实现握手和数据回显最终来成功和这行命令建立连接

```bash
nc -v 10.42.42.2 
```

在tcp的这三次握手中需要我们处理的只有第二次握手，为了简便起见，在这里不在对第三次的握手数据包进行校验。所以我们在这里只需要去实现的就是第二次握手数据包的发送。

[handle\_tcp](../../../../04_protocolstack_underlying_c/first_version/src/tcp.c#16) 这里的逻辑非常清晰。**当宿主机终端敲下 `nc` 命令时，它会向我们的协议栈发送一个带有 `SYN` 标志位的 TCP 报文（第一次握手）。我们的 `handle_tcp` 函数首先会解析出源端口、目的端口以及最重要的序列号（Seq）和确认号（Ack），并通过位运算（`tcp->flag & TCP_SYN`）精准捕获这个建立连接的请求。**

**为了完成第二次握手，我们需要构造一个 `SYN + ACK` 报文发回去。这在代码中体现为以下几个关键的翻转与重构动作：**

1.  **端口对调**：将接收到的源端口变成我们的目的端口，目的端口变成源端口。
2.  **序号推进**：由于对方发来了一个 SYN 请求（消耗一个序列号），我们必须将对方发来的 `Seq` 值加 1，并将其转换为网络字节序后赋值给我们的 `Ack` 字段，以此告诉对方：收到了SYN。
3.  **标志位重设**：将 TCP 标志位设置为 `TCP_ACK | TCP_SYN`。
4.  **偏移量（头部长度）设置**：标准 TCP 头部长度为 20 字节（即 5 个 32 位字），因此我们将 `offset_res` 设置为 `(5 << 4)`。
5.  **底层嵌套重构**：和之前处理 ICMP 一样，我们需要在 IP 层将源 IP 和目的 IP 互换，重新计算 IP 报文总长度（IP 头部 + TCP 头部），并在清零原有 Checksum 后重新计算 IP 和 TCP 的校验和。

在这里着重注意的是两个字段`ack` `seq` 在握手数据包中seq是随机生成的较大数值，在正常的数据包里面就是该头部第一个字节在整个数据包里面的位置，ack是期望对方发过来的第一个字节在整个字节流中的大小，也就是说，在理想情况下，该个数据包的seq就是上个数据包的ack，从这一点也是tcp实现数据流的最基本也是最核心的步骤。

而在成功将握手数据包发送后我们可以在终端看到tcp连接已经被成功建立（`nc` 提示 Connection succeeded），这时候我们可以直接在终端键入字符来发送tcp数据包。下一步我们则将接受到的数据包进行回显。

[handle\_tcp\_data](../../../../04_protocolstack_underlying_c/first_version/src/tcp.c%2394)
需要注意的是这两个函数进行校验和计算的时候都需要在使用伪头部（Pseudo Header）来进行计算，这一点和我们在第三章的陈述完全一致。**伪头部并不真正在网络中传输，它包含了源 IP、目的 IP、协议号（TCP 为 6）以及 TCP 报文总长度。TCP 引入伪头部参与校验的目的是为了做“双重保险”：不仅要确保 TCP 数据在传输中没有损坏，还要确保这个 TCP 报文确实是路由给这个 IP 地址的，防止 IP 层发生路由投递错误。在代码的 `tcp_checksum` 函数中，我们在内存里临时 `malloc` 了一块空间，把伪头部和实际的 TCP 报文拼接在一起送入 `checksum` 函数计算，算完后再释放内存。**

而数据回显也只需要我们对payload进行正确定位。**在 [get_tcp_payloadlenp](../../../../04_protocolstack_underlying_c/first_version/src/tcp.c#85) 函数中，我们通过一个经典的公式来剥离所有协议头：`载荷长度 = IP 总长度 - IP 头部长度 - TCP 头部长度`。如果计算出的载荷长度大于 0，就说明我们收到了用户键入的真实数据。**

**接下来就是把这段数据原封不动地回显。为了实现这一点，我们不仅要进行 MAC、IP、Port 的对调，还要严谨地维护 TCP 的状态：**

  * **新 Ack 的计算**：我们收到了对方发来的 `payload_len` 字节的数据，因此我们必须将对方的 `Seq` 加上 `payload_len`，作为我们回复的 `Ack`，表示完全接收到了对应字符。
  * **新 Seq 的计算**：我们回复数据包的 `Seq` 直接使用对方数据包里的 `Ack` 值即可，因为对方的 Ack 就是它期望我们发送的下一个序列号。
  * **标志位设置**：将标志位设为 `TCP_PSH | TCP_ACK`。`PSH` (Push) 标志位非常重要，它是在告诉宿主机的操作系统：“收到这批数据后，不要在接收缓冲区里缓存等待了，请立刻将其推送到应用层（即立刻在 nc 的终端里打印出来）”。
  * **重新封包**：最后，清零并重新计算修改后的 IP 与 TCP 校验和，通过 `write` 写入 TAP 设备，完成数据链路的闭环。

到这里我们已经成功实现了tcp的回显，从链路层一路向上搭建起了应用层的网络结构，而在接下来的部分中我们将会把这几部分进行进一步的重构最终实现应用级架构和http服务器构建。
